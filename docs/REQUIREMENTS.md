# 产品需求

朋友之间玩的炸金花网页游戏，使用虚拟积分，不涉及任何充值和兑换。规则见 [RULES.md](RULES.md)，前后端通信协议见 [PROTOCOL.md](PROTOCOL.md)。

## 1. 终端与适配

- 同一套页面同时适配手机和电脑，按页面宽度自适应。
- 手机端以**竖屏**为主。电脑端宽屏展示，牌桌居中，两侧可放日志 / 观战列表。
- 重点保证：微信内置浏览器、iOS Safari、安卓 Chrome、电脑 Chrome / Edge。
- 最小支持宽度 320px。禁止页面整体横向滚动，不能出现双指缩放后布局错乱。
- 第一版不做：个人战绩页。

## 2. 安全原则（最高优先级）

- **其他玩家的牌永远不能出现在浏览器里**：不出现在 WebSocket 消息、HTTP 响应、页面 DOM、JS 内存中。
- 服务端只把接收者“有权看到”的牌发给他，规则见 RULES.md 3.7 / 3.9。
- 闷牌状态下，本人的牌也不下发。
- 比大小、判输赢、算积分全部在服务端完成。所有操作都在服务端校验：是不是他的回合、金额对不对、条件满不满足。前端只负责展示和提交意图。

## 3. 账号

- 注册：用户自己填账号 ID 和密码，不做任何验证，注册即登录，然后进入大厅。
  - 账号 ID：3–16 位字母、数字、下划线。唯一性不区分大小写，登录时也不区分大小写。
  - 密码：4–64 位任意字符，服务端用 scrypt 加盐哈希存储。
- 昵称：默认等于账号 ID，大厅里可以修改，1–12 个字符。
- 头像：前端根据账号 ID 自动生成，用 ID 的哈希决定背景色，中间显示昵称首字。不做上传。
- 登录状态保持 30 天。
- **同一账号只能在一处在线**：新登录会让该账号旧的 token 全部失效；新建立的 WebSocket 连接会把旧连接踢下线，旧设备提示“账号已在其他设备登录”。
- 无法找回密码。

## 4. 大厅

- 只有两个功能：**创建房间**、**输入房间号进入**。不展示其他人的房间。
- 显示当前昵称（可修改），提供退出登录。
- 输入房间号时自动去掉首尾空格；房间不存在时提示。

## 5. 创建房间

- 基础配置：局数、初始积分、底注。每项都有快捷选项，也可以自定义输入。
- 高级配置按“下注规则 / 比牌规则 / 牌型规则 / 喜钱 / 时间与超时”分组，每组默认折叠、可以单独展开（也可一键全部展开），组标题下显示当前取值概要；展开后每项都显示中文说明。提交时有错误的组自动展开并定位到错误处。
- 创建成功后进入房间，创建者成为房主。

## 6. 房间

### 6.1 房间号与邀请

- 房间号 8 位，只用小写字母和数字，从以下 30 个字符中随机生成，保证不和现存房间重复：
  - 数字：`23456789`（去掉 0、1）
  - 小写：`abcdefghjkmnprstuvwxyz`（去掉 i、l、o、q）
- 输入房间号、打开房间链接时**不区分大小写**：输入 `A` 等同于 `a`。（旧版本生成的大小写混合房间号同样按不区分大小写查找。）
- 房间链接：`http://<host>/r/<房间号>`。
- “邀请”按钮打开弹窗，里面有：
  - 只读输入框，显示完整链接，可以手动选中复制。
  - “复制链接”按钮：优先用 `navigator.clipboard`；HTTP 下不可用时，降级为隐藏 textarea + `document.execCommand('copy')`；都失败时提示“请长按手动复制”。
  - 房间号单独展示，也有复制按钮。
- 未登录的人打开房间链接：先跳到登录 / 注册页，完成后自动回到该房间。

### 6.2 成员与角色

- 进入房间的人默认是**观战者**，不分配积分。
- 15 个座位。点空座位**入座**，入座时发放初始积分（同一场里重新入座则恢复原积分）。
- 观战人数上限 30。座位和观战都满时拒绝进入。
- 一个账号同时只能在一个房间。进入新房间时自动退出旧房间；如果他在旧房间的对局中还没弃牌，就拒绝进入，并提示先结束那边的对局。
- **改为观战模式**（离开座位）：准备阶段、局间、结算阶段可以；本局对局中（包括已经弃牌）不能，要等本局结束。对局期间入口在“点自己的头像”菜单里，并有二次确认。
- 一场进行中，观战者可以入座，从下一局开始参与。
- 显示：每个座位显示头像、昵称、积分、状态（准备 / 闷 / 已看牌 / 弃牌 / 比牌输 / 本局不参与 / 掉线），以及本局已下注额和庄家标记；轮到某人时显示倒计时。观战者列表显示人数，点开看名单。
- 本人入座后，牌桌以本人为视角，自己固定在底部中央。

### 6.3 房主

- 创建者是房主。房主主动退出时，房主身份立即转给最早入座的在线玩家；没有在线的入座玩家时，转给最早进入的在线观战者。房主掉线超过 120 秒，同样转移。新房主通知全房间。
- 房主权限：
  - 准备阶段修改配置（`initialChips` 除外）。修改后所有人的准备状态自动取消，并通知全房间。
  - 踢人：**任何阶段**都可以，观战者、座位上的人、本局对局中的人都能踢。对局中的人被踢时先自动弃牌（本局已下的注不退还），本局结束后清理座位。踢人时可勾选“不允许再进入本房间”，勾选后在房间解散前不能再进入；不勾选则之后还能再进来。
  - 添加机器人：点空座位（或菜单里的“添加机器人”）往空座位上加机器人，机器人自动准备、自动出牌，可以和真人一起开局；点机器人头像可以移出。
  - 开始游戏。
  - 中途提前结束本场：当前局作废、退还本局下注，然后结算。
  - 结算后选择“再来一场”。

### 6.3.1 机器人

- 机器人只能由房主添加，坐在空座位上，昵称带 🤖。开局、局数、积分、结算与真人完全一样。
- 机器人和真人一样**只知道自己的牌和公开信息**（底池、单注、谁看了牌、轮数），看不到别人的牌。
- 出手前模拟思考 1.4–3.6 秒；闷牌时越往后越倾向看牌；看牌后按牌力决定跟注 / 加注 / 比牌 / 弃牌，偶尔诈唬；赢了偶尔在聊天里说句话。
- 机器人不算“在线人数”：房间里只剩机器人时，照常按“无人在线 30 分钟”销毁。机器人不会成为房主。

### 6.4 准备与开始

- 入座的非房主玩家可以点“准备 / 取消准备”。
- 房主不需要准备，点“开始”即视为准备好了。房主可以不入座，只观战并主持房间。
- 开始条件：至少 2 人入座，且入座的非房主玩家全部已准备。不需要坐满。

### 6.5 对局中

- 顶部显示：房间号、第几场、剩余局数（例如“第 3 / 10 局”）、规则查看按钮、邀请按钮、退出按钮。
- 牌桌中央显示：底池、当前单注（同时显示闷价和明价）、当前轮数 / 轮数上限。
- 本人区域：
  - 3 张牌，闷牌时显示牌背，点击或“看牌”按钮翻开。
  - 操作栏：看牌、弃牌、跟注（显示金额）、加注（列出可选档位和金额）、比牌（选择对手）、孤注一掷（条件满足时）。不可用的按钮置灰。
- 比牌时有动画，并展示比牌结果。
- 一局结束时展示结果：赢家、赢得积分、喜钱、开牌结果，以及下一局（或结算）的倒计时，时长由房间配置决定。赢家可以点“亮牌”。
- 操作日志面板，显示最近的操作记录。

### 6.5.1 聊天

- 房间内所有成员（入座玩家和观战者）都能发文字消息（最多 60 字）、表情（24 个常用 emoji）和快捷语。
- 入座玩家发的消息会在其头像旁冒出气泡，停留约 4 秒；观战者的消息以弹幕条形式在牌桌上方飘过。
- 手机端在牌桌右下角有聊天按钮（带未读数），点开是底部抽屉；电脑端聊天面板常驻左侧栏。
- 房间保留最近 50 条消息，新进入或重连的人能看到。同一人发言间隔至少 0.8 秒。

### 6.5.2 声音

- 背景音乐、音效、语音播报三项分别开关，默认全开，设置只保存在本机浏览器，不影响房间里其他人。
- 口播用火山引擎豆包语音合成 2.0 预先合成为静态文件（`client/public/audio/voice`），音效和背景音乐由脚本合成（`tools/audio`）。
- 玩家声音包（9 个，含东北话、四川话、粤语）每人自选，保存在账号上，同桌所有人听到的都是该玩家选的声音；没选过的按 userId 自动分配。荷官播报风格（标准 / 搞笑解说 / 东北话 / 粤语）和三路音量、立体声方位只影响自己。
- 互动道具：点别人的头像可以送花、飞吻、干杯、点赞、扔鸡蛋、番茄、炸弹（同一人两次至少间隔 2.5 秒），所有人都能看到飞行动画、听到命中音效和对方的反应。

### 6.6 结算与再来一场

- 打满局数，或房主提前结束后，弹出本场结算榜：排名、净输赢、本场拿到过的最大牌型、赢的局数。
- 显示“历场累计输赢”。
- 房主看到“再来一场”按钮。点击后回到准备阶段，可以修改配置；所有入座玩家的积分重置为初始积分，准备状态清空。成员不用重新进入房间。

### 6.7 掉线与重连

- 掉线保留座位，轮到他时正常计时，超时按规则处理。下一局开局时如果仍离线（超过 10 秒），自动改为观战模式，积分保留。
- 刷新页面或网络恢复后，自动重连并恢复全部状态，包括已经看过的自己的牌。
- 断线期间页面顶部显示“连接中…”。

### 6.8 房间销毁

- 房间内没有任何在线成员持续 30 分钟后，自动销毁，房间号作废。
- 服务重启后，所有房间都会丢失。账号和战绩存在数据库里，不会丢。

## 7. 部署约束

- 服务器配置低（2 核、1.8G 内存），只跑一个 Node 进程，同时提供静态页面、HTTP API 和 WebSocket。
- 数据库用 Node 内置的 `node:sqlite`，单文件，不装 MySQL / Redis。
- 进程由 systemd 守护。部署细节见 [DEPLOY.md](DEPLOY.md)。
